# Usage baseline observations (incomplete)

**Historical capture, not a port gate.** The owner replaced exhaustive baseline capture with a [source-led port](../designs/native-usage.md#compatibility-baseline). Keep these synthetic fixtures as reference data; do not expand coverage instrumentation or require the pending ledger to clear before implementation or cutover. They do not qualify a native replacement. Package selection and installed runtime behavior are untouched.

The reproduction and coverage details below describe the earlier capture method, including unfinished counter-replay work. They are retained for audit, not current acceptance requirements. `npm test` runs package and native port checks; `npm run test:usage-baseline` explicitly runs the historical capture suite.

The retained ledger has **1,657 pending source outcomes** (3,493 witnessed), including 56 [named gaps](#named-gaps). These are historical capture limitations, not blockers on the source-led port. Required safety behavior is tested directly in Go.

The public `usage:*:v1` event API is not ported ([ADR 0004](../adr/0004-no-public-usage-event-api.md)); the native collector feeds the footer in process. Its 254 ledger outcomes are marked `out-of-scope` with that reason and are not counted as pending. The footer's own `usage:changed:v1` listener is not among them: it holds the footer's session, session ID and provider fence, which stays in scope at the collector-to-footer seam. The [Go/Node boundary](#gonode-boundary) captures remain as the evidence for that decision.

The historical `--check` command attempts to reproduce the retained closure; no current passing replay or native qualification is claimed here.

## Reproduce

After `npm ci`, run:

```sh
GOMAXPROCS=2 GOFLAGS=-p=2 npm run test:usage-baseline
```

This optional historical suite runs `node probes/usage-baseline.mjs --check`. The probe launches the complete selected package, a probe-only Go peer (`probes/usage/bridge`) and a disposable observation extension in a real PiG RPC process. It starts with synthetic DeepSeek host credentials and supplies additional synthetic credentials only in disposable host-auth fixtures. It replaces Node fetch transport with an explicit loopback endpoint. Synthetic Codex model prompts, with synthetic credentials, take the PiG host's own request path to the same loopback listener: the host's `HTTPS_PROXY` points at it, it accepts only a `chatgpt.com:443` tunnel, and it terminates TLS with a per-run certificate authority from `probes/usage/tls` that the host trusts only through `SSL_CERT_FILE`. Any other tunnel or unplanned model request fails the run. Effective provider URLs are unmodified before the substitution. Missing fixture routes fail the run. The environment is allowlisted; personal auth, sessions, settings and ambient extensions are not imported. `TZ=UTC` and the `en_US.UTF-8` locale are explicit, and the resolved Node formatting locale is retained with the observations.

The probe owns its HTTP server and PiG process, closes input, waits for exit, and verifies all observed descendants have disappeared. It uses disposable roots and a reusable build cache under `.pb/probes/7/`; process handles are recorded in that scratch's `pids` ledger. Linux `/proc` is required for the retained RSS/descendant protocol. No macOS measurements or live-provider qualification are claimed.

To refresh retained observations, run the two commands in this order:

```sh
node probes/usage-baseline.mjs --measure
node probes/usage-baseline.mjs --capture
```

`--capture`, `--check` and `--observe` also replay the registered lifecycle fixtures in two more disposable PiG processes: once with the selected package and once with a **source composition**, the production usage member (`extensions/pig-status-usage.ts`) with only its backend import switched from the installed dist to the shipped source. Both replays must produce exactly the full run's lifecycle requests and RPC UI, and the source replay must produce the dist replay's receipts and host error lines. The source replay's backend `src/` windows are then added to the matching registered windows, tagged `composition: "source-replay"`; each witness they supply carries that tag. A lifecycle-only replay runs without the provider, consumer and API captures, so its invalidation receipts differ from the full run's; that is why receipts are compared replay to replay. `--lifecycle-observe` does not replay: it writes nothing retained and its consumers check only behaviour.

`--capture`, `--check` and `--observe` then run one more full replay, the **exact-counter replay** (owner decision, 2026-10-31, third set). It answers the outcomes V8 block coverage cannot count: skipped right-hand sides, `if` false arms without `else`, loop exits, `try` outcomes and optional links in last-statement positions.

1. `probes/usage/counter-replay.mjs` writes a disposable copy of the pinned backend `src/` tree. Each branch outcome gets one counter: `if` and conditional conditions, logical right operands, optional links (lowered to helper calls that keep the receiver and read each property once), `catch` entries, `try` completions and throws, loop bodies, normal loop exits (a `break` that leaves the loop sets a flag, so it is never a normal exit), zero-iteration exits and `case` selections. All 5,256 backend source outcomes get a counter; none is left uninstrumented.
2. Before anything runs, an independent erasure walks the instrumented AST, removes the counting code and must reproduce each pinned source file byte for byte. Each counter's erased position must match exactly one ledger obligation, and the manifest must list every backend source outcome exactly once. Otherwise the replay fails.
3. The copy runs in a disposable PiG process with every fixture: providers, consumers, API captures and registered lifecycle fixtures. The production usage member imports one copy; the observation extension's direct source imports use a second copy, so module state stays separate as in the uninstrumented run. Its requests, RPC UI, receipts and results must equal the uninstrumented run exactly, and its own source/dist comparisons must pass.
4. Each fixture window records the positive counter deltas, tagged `composition: "counter-replay"`. The raw replay output and the manifest are kept by SHA-256 under `.pb/probes/7/raw-counters/`.
5. The ledger regenerates the manifest from the pinned source and rejects any difference. A counter witness counts only for an armless `src/` outcome that has no V8 witness. Every V8 witness, arm or count rule, source or dist, must have a positive counter for the same outcome in the same window, or the build fails. An armless outcome the counter replay counted zero times in every window keeps a pending reason that says so; it needs an observing fixture.

`probes/usage/counter-replay.test.mjs` proves the counters sound: real executions of instrumented modules give exact counts for every outcome kind, never count an outcome that did not run (throwing conditions and operands, short-circuited later links, `break`, `return` and `throw` out of loops, `return` out of `try`) and behave like the uninstrumented module. Six mutated counting helpers each fail a control, and five structural tamperings (swapped indices, a removed `break` flag, a moved counter, a stray counter, a changed source character) each fail verification.

`--measure` records three non-profiling package samples. `--capture` records observations, inventory, ledger, provenance and one instrumented sample, and keeps package samples whose measurement identity matches. `--check` fails when retained measurements belong to another identity, when fewer than three package samples exist, or when the instrumented sample is missing.

A capture is a baseline update, not a passing qualification decision. Review its changes independently. `--observe` leaves raw, synthetic-only transcripts in scratch without updating retained expectations. Neither the observation extension nor the Go peer is a package member; the transport preloader is selected only in the isolated child environment.

## Go/Node boundary

This characterization of callback acceptance, cancellation, session identity, result timing, invalidation and capabilities is the evidence for [ADR 0004](../adr/0004-no-public-usage-event-api.md). It does not gate checkpoint 2. `probes/usage/bridge.mjs` and the probe-only Go peer in `probes/usage/bridge/` capture six `protocol:go-bridge:*` rows in the same real PiG process as the production composition. The Go peer subscribes to the usage channels only while the capture window is armed, so production usage events elsewhere in the run are unaffected. `verifyBridge` asserts each finding below on every check.

| Direction | Event | Observed |
|---|---|---|
| Node → Go | `usage:query:v1`, `usage:capabilities:v1`, `usage:changed:v1` with the production session reference | The host's relay to the Go realm fails with `Converting circular structure to JSON`. The Go listener receives nothing. Node listeners still run; for query and capabilities the production backend offers a result to the Node sender. |
| Node → Go | `usage:query:v1` without a session reference | The Go listener receives the event during the Node emit. `respond` is absent, `signal` arrives as an empty object and `sessionId` matches the host session. Without the session reference the production backend makes no offer. |
| Go → Node | `usage:query:v1`, `usage:capabilities:v1` | The Node listener runs before the Go emit returns. It sees no `respond` function, no `AbortSignal` and no composition session reference; `sessionId` matches. The production backend rejects the request and makes no offer. |

What this means for each contract element:

- **Callback acceptance:** a Go listener cannot accept or answer an offer; a Go sender cannot receive one.
- **Cancellation:** abort state never crosses; a Go-side `signal` is plain JSON.
- **Session identity:** the production session object cannot cross. Session-bearing events fail relay outright; only `sessionId` crosses.
- **Result timing:** delivery is synchronous in both directions when it succeeds, so ordering is preserved, but no result channel exists.
- **Invalidation:** `usage:changed:v1` carries the session reference, so the Go realm never receives it.
- **Capabilities:** same failure as query.

A native backend that keeps the public `usage:*:v1` contract therefore needs one of: a host API change that carries callbacks, signals and session identity across realms; a Node shim that stays in the package; or an explicit decision to change or retire the public API. The design takes the third option: the public API is not ported ([native usage scope](../designs/native-usage.md#scope-and-current-state), [ADR 0004](../adr/0004-no-public-usage-event-api.md)).

## Observed boundaries and unresolved work

1. **Session identity matters.** An independent Node extension's own `ctx.sessionManager` differs from the production composition's manager even when session IDs match. Its requests receive no offer. Observing the composition's existing query payload supplies the original session handle: using that handle reproduces capabilities, cache-miss, fresh reports and cancellation. A plain JSON session substitute cannot establish native parity; the Go/Node captures above confirm it.
2. **Some frozen adapters follow before rejecting.** Codex, Copilot, OpenRouter, OpenCode Go and Z.AI use fetch's default redirect mode. The local same-origin redirect capture observes a second credential-bearing request before the backend rejects `response.redirected`. Guarded adapters using `redirect: error` make only the first request. This is existing backend behavior, not evidence that the design's reject-before-forward safety requirement passes. No production behavior was altered to hide this discrepancy.
3. **Consumer coverage is incomplete.** Remaining auth branch combinations and real selected-model/request/publication interleavings; registered settings UI and transactional races; terminal menus and current/other/all selection; bounded cache/backoff/stale publication; and reload/replacement/interrupted shutdown still need branch-matched executable fixtures. The registered Codex batch covers reset discovery, confirmation, stable retry, outcomes and credential-candidate failures, and Fast catalogue discovery, toggles, request-tier and message-cost hooks, and the `(Fast unknown)` decoration with its standard-tier prompt fallback, but not every branch. Successful registration, API examples and ordinary EOF shutdown do not substitute for these cases. The standalone captures cover slices of these categories, not every branch or their registered lifecycle paths; settings UI and complete consumer interleavings remain unexercised.
4. **Time is synthetic.** Child Node `Date.now()` is fixed for portable reports and request windows; monotonic parent timing is real. Explicit timestamps exercise standalone cache TTL and report-reset formatting; standalone deadline cases use real bounded timers. These do not exercise host expiry races, minute repaint, scheduled refresh or request timeout interleavings. Those need separate controlled-time/lifecycle fixtures.
5. **Adapters are not host auth.** Direct source/dist scenarios use explicit synthetic resolved-auth inputs and guard callbacks. The installed composition's DeepSeek API refresh exercises its selected-provider query path. The real-registry public-function cases exercise host resolution for all 18 providers, but do not establish those providers' registered command/lifecycle/query-publication paths.
6. **Pending outcomes need two kinds of work.** Each pending obligation's `pendingReason` names its kind. Of the 1,657 pending outcomes:
   - 610 have an arm but no positive uniquely matched witness in the retained windows. Most need new fixtures. For code that ran only as installed dist, attribution fails closed on optional calls with no argument, rewritten negations, renamed imports, await-wrapped conditions and same-line duplicate conditions.
   - 480 have an applicable count rule whose bound is not positive in any window; they need fixtures that take the outcome.
   - 4 have no arm and no uniquely matched runtime branch in any window, so no rule could be evaluated; they need an observing fixture first.
   - 507 have no sound count rule at their position (235 skipped RHS, 92 non-first or return-position optional links, 70 `if` false, 56 loop exits, 50 `try` outcomes, 4 case selections); they need a stronger observation rule, never an exemption.
   - 56 are [named gaps](#named-gaps).

   By source file, the largest groups are `src/usage.ts` (541), `src/format.ts` (192), `src/query.ts` (145), `status/usage.ts` (94, 45 of them named gaps), `src/usage-settings-ui.ts` (81), `src/codex-fast-runtime.ts` (76), `src/codex-fast-catalog.ts` (74) and `src/providers/openai-companion-usage.ts` (60).
7. **The footer's report path is unreachable in the baseline.** The footer only sends cache-only queries (`refresh: false`), and the pinned backend answers every cache-only query with `cache-miss` before it reads any cache. The footer therefore never receives a ready report: its report-to-window conversion, window expiry filter and rejection handler have no reachable baseline behavior. The owner listed these outcomes as [named gaps](#named-gaps); the native footer seam must define that behavior from the design, not from this baseline.

No live endpoints, real credentials, redemption, billing state, consumer activation, publication or personal files were used. No native collector has been implemented or activated.

## Named gaps

A named gap is a source outcome the baseline cannot reach for a recorded reason, with an explicit owner decision. It stays `pending` in `usage/branch-ledger.json`, with a `namedGap` record and a pending reason that starts `Named gap:`. It is not observed, not out of scope and not waived.

**Reset credential-candidate discovery failure** (owner decision, 2026-10-31):

- Outcomes: the throw outcome of the `try` that emits `oauth:credential-source:v1` in `collectOAuthCredentialCandidates` (`src/oauth-credential-source.ts`) and the entry of its `catch`, which returns `{ ok: false }`.
- Reason: PiG's event bus wraps every listener in a handler that catches and logs its error (`Event handler error (<channel>): …`). `emit` itself throws only when the host transport call fails or for an unhandled `error` channel, neither of which a registered listener can cause.
- Executable proof: `lifecycle:reset:candidates-source-throws` arms a credential-source listener that throws after the reset menu loads. PiG logs the error, discovery proceeds and the reset endpoint is requested. `lifecycle-evidence.mjs` asserts all three.
- Native obligation: the Go port must prove fail-closed credential-candidate discovery at its own seam with a unit test.
- The fail-closed branch in `resolveCodexResetAuth` (`!offered.ok`) is still witnessed through the public function with a candidate reader that reports failed discovery (`resets:auth:discovery-denied`), as its `query.ts` siblings are. The owner accepted that witness (2026-10-31, second set).

The owner's second decision set (2026-10-31) adds the gaps below. Each row's `pendingReason` states the invariant that makes it unreachable. The ledger fails to build if a listed selector stops matching its exact outcome count, or if any named-gap outcome gains a witness.

**Readiness emit failure** (2 outcomes, an extension of the gap above):

- Outcomes: the throw outcome of the `try` that emits `oauth:credential-readiness:v1` in `waitForOAuthCredentialSources` (`src/oauth-credential-source.ts:77`) and the entry of its `catch` (line 79), which returns `false`.
- Reason: the same PiG listener containment. Readiness failure itself is witnessed through a rejected `waitUntil` (`lifecycle:reset:candidates-unready`).
- Executable proof: `lifecycle:reset:candidates-readiness-throws` arms a readiness listener that throws. PiG logs `Event handler error (oauth:credential-readiness:v1): …`, readiness succeeds and discovery proceeds to the reset endpoint. `lifecycle-evidence.mjs` asserts all three.
- Native obligation: prove fail-closed readiness, including a failing readiness emit, at the native Go seam.

**Footer report path** (52 outcomes in `status/usage.ts`):

- Outcomes: every outcome in `finite` and `reportWindows` (lines 46–66); the `publish` filter and deadline map callbacks (lines 111 and 113); the line 114 false arm; the line 140 ready branch; the `response?.` nullish arms (lines 139 and 140); the line 147 rejection handler; and the line 134 true arm.
- Reason: the footer sends only `refresh: false` queries. The pinned backend settles every one with an unavailable result (`cache-miss` at `usage-api.ts:278`, or an earlier failure or cancellation reason) before it reads any cache, so no ready report reaches the footer. `publish` therefore only ever keeps an empty window list. The backend's offered promise always resolves to a plain result object and nothing rejects it. The backend calls `respond` exactly once, synchronously, before the footer can abort that query.
- The owner's third decision set (2026-10-31) adds seven rows with the same proof:
  - line 134, skipped right-hand side of `accepted || signal.aborted`: skipping needs `accepted` to be true at a `respond` call, which only a second call for the same query can see. The backend calls `respond` once per query.
  - line 140, the four right-hand-side-evaluated outcomes of the ready `&&` chain: each right operand runs only after the leftmost operand, `response?.status === "ready"`, is true, and no ready report reaches the footer.
  - line 140, both outcomes of `ctx.model?.provider`: it is the right operand of `report.providerId === …`, which runs only after the ready status and the report are both truthy.
- Native obligation: define and prove the native footer's report rendering (window conversion, expiry filter, deadline timer and failure handling) at the Go collector-to-footer seam from the design.

**Defensive guards** (7 outcomes):

- `src/providers/kimi-coding.ts:134` `row?.reset_time` nullish: line 133 returns unless `row?.used_ratio` is a number, so `row` is an object.
- `kimi-coding.ts:180` `!currency` true: the only currencies are `asCurrency` results matching `/^[A-Z]{3}$/`.
- `kimi-coding.ts:183` true and skipped-RHS arms, and `:232` false and skipped-RHS arms: `fixedPointToMajor` receives only safe non-negative integers, and dividing by 1,000,000, rounding and dividing by 100 keeps the result a finite safe value.
- `src/codex-resets.ts:103` `!adapter` true: `adapterForProvider("openai-codex")` looks up the module constant `SUPPORTED_ADAPTERS`, which contains that adapter and which no backend code mutates.
- Native obligation: the native port keeps equivalent guards.

## Settings/auth batch boundary

`probes/usage/settings-auth.mjs` adds 316 source/dist scenarios: 278 real-host auth cases, 25 settings normalization boundaries, 12 filesystem transactions and one default-path observation. All run in the same real PiG process as the selected mixed package. Host auth uses the actual `ctx.modelRegistry` and host-registered models; it never substitutes an already-resolved registry. A scoped model view selects the host model for the public resolver without altering the production composition's selected DeepSeek model. Actual `/usage` other/all selection and model-change lifecycle belong to the registered batch below.

Host OAuth registration explicitly supplies an offline `getApiKey` returning the synthetic stored access. Login/refresh callbacks throw if called. Registry refreshes disable network. Frozen source and installed-dist credential readers emit the real `oauth:credential-readiness:v1` and `oauth:credential-source:v1` events and use real host-root `readStoredCredential` fallback. Readiness rotation writes the disposable auth file before fresh provider/model resolution; every fixture write of `auth.json` holds `auth.json.lock`.
